## 当前最高优先级：P0 主线闭环 / Next Todo

**下一版只以真实 LLM 基础链路跑通为目标。先完成一条可重复演示、可保存、可回看的真实流程，再进入质量优化与正式上线阶段。** 本节定义整体主线目标；**当前无需 API Key/GPU 的具体执行入口为 [本轮改动与验收清单 A0–A7](./PRE_LLM_MAINLINE_CHECKLIST.md)**，后续改动逐项对应该清单。后文旧 P0、R0–R8 及历史报告保留事实，不再作为本版必须全部关闭的前置清单。

```text
用户登录并选择语言
  → 创建/选择项目和问卷，配置角色、题目/访谈提纲与研究描述
  → 保存配置并开始一轮真实 LLM 调研
  → 后端把角色、问题、语言、研究背景及访谈历史传给模型
  → 将合法回答渲染到问卷/对话页面
  → 配置、角色、轮次、回答/对话与状态写入 PostgreSQL
  → 刷新、关闭后重新进入或重新登录
  → 从 DB 重新读取历史问卷、角色配置与调研结果
```

### 范围约定

- **一个真实端点先跑通**：根据先到位的资源，选择云 API 或本地模型服务。另一来源保留接入边界，后续接入；不等待 Token 和 GPU 同时就绪，不把四组合双来源验收设为本版门槛。只宣称实际验证过的来源。
- **两种业务模式都覆盖**：问卷与固定提纲访谈；访谈回答带同一受访者的历史上下文。保留现有角色维度与 text/choice/scale，choice 本版仍为单选；自定义维度、多选、新的 Agent 编排不在本版展开。
- **沿用已实现底座**：复用账号/语言、草稿、版本、Repository、DB、前端展示和历史入口；先验证现有能力，只改实际阻断链路的部分。
- **基础信息范围明确**：项目/问卷名称、研究描述、角色配置、题目/提纲、运行时间/状态、回答/对话和实际模型来源；已有基础人数/进度可保留。画像/态度推断、情绪分析不是主线完成条件，真实模式下尚未接入的模块关闭或显示未启用，不能混入 Mock 结果冒充真实分析。
- **规模有界**：先用少量角色与题目、一个部署环境和现有进程内执行器。配置服务端凭据和有限请求超时，失败可见，不做无限重试；不先建设生产级调度、计费或可观测平台。

### 本版完成定义：一条可重复的验收脚本

在一个可用真实端点、一个现有浏览器桌面环境中，以少量角色和题目完成以下操作，并记录实际使用的模型和轮次 ID：

1. 使用已有账号登录，选择中文；创建/选择项目和问卷，修改角色、研究描述和题目，确认草稿保存。问卷覆盖文本、单选和量表。
2. 启动问卷，确认角色、问题及语言进入真实模型请求，页面显示合法回答和完成状态，配置与结果落入 PostgreSQL。
3. 刷新页面，检查同一问卷、角色、轮次和结果；关闭后重新进入，再登出/登录，从历史打开同一轮次。修改当前草稿不改变历史内容，历史回看不触发新模型调用。
4. 用固定提纲访谈重复生成、保存和回看，至少两道关联问题验证上下文。检查项目/问卷名称、时间、状态和模型来源等基础信息。
5. 切换英文，用小样本完成问卷与访谈的相同核心链路，检查界面/API/模型输出的语言约定；历史仍保留原轮次配置与语言。用第二个已有账号抽查历史隔离不退化。
6. 做一次请求失败或超时检查：页面有错误状态、不产生虚假成功结果；恢复端点后可以重新发起。正常耗时的真实调用不被租约误中断。

以上通过且本次改动相关的测试/类型/构建检查通过，即标记 **“P0 主线闭环已完成（已验证来源：具体来源/模型）”**，进入下一阶段。无需等待另一推理来源、五账号×五视口全矩阵、全部故障注入、三范围导出、推断任务级重试和正式运维验收。该完成状态只表示 Demo 主线跑通，不表示正式生产上线。

### 范围控制与停止规则

- 新问题只有造成上述脚本无法完成，或造成错误数据保存/串用户/历史丢失，才加入本版 P0；必须指出阻断的 M 步骤并采取最小改动。

## 当前项目现状

### 产品与数据状态

系统面向公共政策科研，目标是用 LLM 模拟不同人群的问卷回答与访谈反馈，辅助实际调研设计和假设发现，降低前期数据收集负担。计划支持公有云 API 与本地 GPU 推理服务；共用的异步 HTTP 接口已实现；实际云端/GPU 端点尚未验收。默认使用 FastAPI Mock Engine，显式配置后使用 HttpEngine。研究者通过五个预置应用用户之一登录，创建自己的项目和问卷，自动保存草稿，固化不可变问卷/完整配置版本，受控运行研究轮次，查看明确口径的分析和异常证据，并生成有记录的范围化导出。

生产部署模型由 Next.js frontend、FastAPI backend 和 PostgreSQL db 三个独立 Compose 服务组成。PostgreSQL 使用 named volume；普通 restart、容器重建和普通 `docker compose down` 设计为保留数据，只有显式 `down --volumes` 删除数据。

2026-09-19 已真实构建并启动 frontend/backend/db，迁移到 `20260912_0002`，三服务健康。五账号 API 隔离、草稿/版本、运行控制、范围导出、restart/down-up、备份及两次隔离恢复通过。首次启动发现并在工作区修复模板资源未打包；2026-09-26 复核确认资源尚未被 Git 跟踪，交付事项见 M0（原 R0）。浏览器历史/分析/下载可用，五视口无页面级溢出；完整业务矩阵尚未完成。

同时发现影响正确性和真实 LLM 接入的缺口：非法选项答案进入有效统计、推断全失败仍标记完成、长调用过租约被误暂停，以及同步模型边界、无调用追踪、后端无外部出网。详见 [现场与 LLM 准备度报告](./verification/2026-09-19-live-deployment-and-llm-readiness.md)。

## 当前能力边界

- 默认 Mock 回答和辅助推断仍是演示数据；HTTP 回答已通过测试端点验证，实际模型效果待验。HTTP 不混入 Mock 情绪/画像/态度分析，基础题目统计继续可用。
- 用户由部署者在产品外管理；没有注册、忘记密码、应用内用户管理、项目共享、角色或跨用户管理员读取。
- 当前已支持固定人口字段；自定义字段、运行前设计检查、配额、试跑提升、研究批注和跨轮对比留待后续迭代。
- 运行器位于 FastAPI 进程内，没有 Redis/Celery；数据库租约和检查点提供 P0 恢复语义，不提供生产级分布式任务 SLA。
- Quick Tunnel 是临时、可选、无固定地址/正式 SLA 的开发演示入口。
- 没有 `DATABASE_URL` 时，后端可以为纯业务测试装配内存 test double，但完整应用认证与持久化工作流不可用；这不是当前部署架构。

### 云端与本地分别需要提供什么

- **云端路径**：供应商、可调用模型名、endpoint、有效服务端凭据及可用额度/限额；后端出网/代理和证书配置。凭据仅由服务端引用，研究者界面无需输入或获取部署密钥。
- **本地路径**：GPU 型号/显存/数量、驱动与运行环境、可用模型权重、上下文长度、推理服务地址与访问认证、并发/队列容量。建议模型服务独立于 FastAPI；若两个端点协议兼容可复用同一 HTTP client，但仍须分别验收格式、usage、超时和容量，不能把“有 GPU”当作已有模型服务。
- **共有部分**：统一请求/响应结构、严格校验、配置快照和调用记录。固定人口画像可先保留为显式合成抽样方案，不必先用 LLM 生成人物；随机扩展字段须注明来源并冻结。自动生成问卷、RAG、智能追问、复杂配额、Redis/Celery、协作和大规模调度可后置。
