## 当前项目现状

### 产品与数据状态

系统是一套使用 FastAPI Mock Engine 的可交互调研平台。研究者通过五个预置应用用户之一登录，创建自己的项目和问卷，自动保存草稿，固化不可变问卷/完整配置版本，受控运行研究轮次，查看明确口径的分析和异常证据，并生成有记录的范围化导出。

生产部署模型由 Next.js frontend、FastAPI backend 和 PostgreSQL db 三个独立 Compose 服务组成。PostgreSQL 使用 named volume；普通 restart、容器重建和普通 `docker compose down` 设计为保留数据，只有显式 `down --volumes` 删除数据。

后端、前端与生产恢复整改均已通过独立静态审查，静态实现交接获批；这不能替代现场验收。2026-09-18 初始 Docker 探测因本地 socket 不存在失败；启动 Docker Desktop 后 socket 出现，但状态持续为 `starting` 且服务端 API 返回 500。`docker compose build`、真实容器/volume、迁移/种子、恢复、五账号和五视口完整浏览器验收仍未执行。

## 当前能力边界

- 回答、情绪、推断和样例数据来自 Mock 实现，不是实时模型调用，也不代表真实受访者或正式研究结论。
- 用户由部署者在产品外管理；没有注册、忘记密码、应用内用户管理、项目共享、角色或跨用户管理员读取。
- 固定人口字段、运行前设计检查、配额、试跑提升、研究批注和跨轮对比仍属于 P1/P2。
- 运行器位于 FastAPI 进程内，没有 Redis/Celery；数据库租约和检查点提供 P0 恢复语义，不提供生产级分布式任务 SLA。
- Quick Tunnel 是临时、可选、无固定地址/正式 SLA 的开发演示入口。
- 没有 `DATABASE_URL` 时，后端可以为纯业务测试装配内存 test double，但完整应用认证与持久化工作流不可用；这不是当前部署架构。

## P0 完成定义与当前判断

以下 12 项必须全部通过，P0 才能从“验收待补”改为“已完成”：

1. 五账号真实登录和跨用户列表/直接访问隔离；
2. 项目、问卷和草稿真实持久保存；
3. 每轮绑定不可变问卷和完整配置版本；
4. backend restart、容器重建及普通 down/up 后轮次仍可打开；
5. 暂停、继续、取消和两种派生重试；
6. 历史复制不修改原版本/结果；
7. 分析始终展示总体、筛选、有效、排除口径；
8. 终止/失败汇总并下钻到证据；
9. 保存/导出状态、三种范围、文件名和记录；
10. 三服务部署、volume、备份恢复和可选公网入口有可执行文档；
11. 后端、前端、数据库、Docker、构建和五视口浏览器闭环通过；
12. README、迭代台账和部署手册与实测事实一致。

当前自动化覆盖上述行为且最终静态审查已通过，但第 1–11 项所需的 live Docker/browser 证据尚不完整，总状态为“静态交接获批/现场验收待补”。
